How one attention head works, neuron by neuron

An illustrated guide to Q, K, V and the T in KT in a Transformer. The whole attention head is built from the same two parts as your skip-gram network: neurons that add up weighted inputs and apply an activation function, and synapses that each carry one weight. Every matrix product, dot product and softmax below is opened up into the neurons and synapses that compute it.

How the numbers were made. The repo has no attention code yet, so this page builds one attention head out of the classes you already have: Neuron in neuron.py and Synapse in synapse.py. The worked example (three tokens, "the cat sat") was built neuron by neuron with those classes and checked against the usual matrix formula. Both gave the same answers. The interactive network in section 10 rebuilds it in your browser so you can try it yourself. Code links are pinned to commit c1f0f57.

1. What one attention head does

Take the sentence "the cat sat". To process "sat" well, the model needs information from earlier tokens: who sat? An attention head lets each token gather information from the other tokens. It does this by giving every token three new vectors, each made from the token's input vector x:

  • Query q: "what am I looking for?"
  • Key k: "what do I contain?" Each query is compared against every key.
  • Value v: "what I pass on if I am picked."

Query and key in plain terms

Think of each token as a person at a meeting, where everyone may ask everyone else for help. A token's query is the question it holds up to the room, such as "I'm a verb. Who did me?" A token's key is a label on its chest saying what it can help with, such as "I'm a noun, and I could be the one doing something." Each token compares its query with every other token's key, and the better the match, the more attention it pays. A library works the same way: the query is what you type into the catalogue search, the keys are the subject labels on the books, and the values are the contents of the books you take home.

Two caveats. These are human-readable stand-ins. In a real model, queries and keys are just lists of numbers, and nobody writes "who is doing the sitting?" anywhere. Training finds whatever questions and labels help predict the next token, and many of them don't map neatly to grammar terms. Also, a model has many heads, and each asks its own kind of question: one might track subjects and verbs, another pronouns, another the previous word. The worked example on this page, where "sat" pays most of its attention to "cat", is the first row of the table, with made-up numbers.

What kinds of relationship?

For each pair of tokens, a head's query and key give one number: how relevant token j is to token i. The kind of relationship isn't written anywhere. It's implied by which head you are looking at, because each head learns its own W_Q and W_K. Three points sharpen this:

  • It's one-directional. "sat" looking at "cat" (q_sat · k_cat) is a different number from "cat" looking at "sat" (q_cat · k_sat), because queries and keys come from different weights.
  • Q and K only decide where to look. What gets passed along is decided by V (and W_O). A head can learn "find the subject" with Q and K, and "copy its number and gender" with V.
  • Nobody chooses the relationships. Training keeps whatever helps predict the next token. The categories below come from researchers studying trained models afterwards.
KindWhat the head doesExample

Not every head is this tidy. Many mix several patterns, or do things nobody has named. As a rough tendency, lower layers have more positional and grammatical heads, and higher layers more semantic and task-specific ones. No single head explains much on its own: meaning comes from many heads across many layers working together, plus the MLP layers between them.

The whole head in one formula

The head compares a token's query with every token's key to get a score for each pair. It turns each token's scores into weights that add up to 1, using softmax. Then it hands each token the weighted mix of all the values. Written with matrices, the whole thing is one line:

Attention(Q, K, V) = softmax( Q · KT / √dk ) · V

Q, K and V are the queries, keys and values stacked up as matrices, one row per token. KT is K transposed, meaning its rows become columns. The T is not a fourth vector. It is the bookkeeping that makes Q · KT come out as a grid of every query times every key (see Step 4). dk is the length of each query and key vector.

To keep every neuron drawable, the example is tiny. There are 3 tokens, each input vector x has 3 numbers (d_model = 3), and each query, key and value has 2 numbers (d_k = 2). GPT-2 small uses d_model = 768 and d_k = 64, but the wiring is exactly the same. In a real model, x is the token's embedding, the same kind of vector your skip-gram code learns, plus some information about its position in the sentence. Section 2 shows exactly where it comes from.

tokenx (input)q = x · W_Qk = x · W_Kv = x · W_V

2. Where x comes from

Compareembedding / context_vectorskip_gram_network.py lines 52–58Two tables of vectorsskip-gram guide

In the first attention layer, x is a token's embedding with its position added on. The embedding part works exactly like the embedding in your SkipGramNetwork. There, feeding in a token switches its input neuron to 1 and every other input neuron to 0 (a "one-hot" input). Each hidden neuron then picks up one weight, so the hidden layer's values are that token's row of the embedding table. A Transformer does the same, and adds a second one-hot layer for position that feeds the same neurons:

So the skip-gram embedding and the first-layer x are the same kind of thing: a learned row of a table, picked out by a one-hot input. There are four differences:

  • How the table is trained. Skip-gram trains its embeddings with the guess-the-neighbour game. A Transformer trains its embedding table together with everything else (W_Q, W_K, W_V and the rest), using one loss: how well it predicts the next token. You could start the table from skip-gram vectors, and some early models did, but modern ones learn it from scratch.
  • Position is added in. A skip-gram embedding for "cat" is the same wherever "cat" appears. Attention needs to know the order, though. On its own it would treat "the cat sat" and "sat the cat" identically, because every token is compared with every other in the same way. Adding a position vector makes each x say both which token and where. GPT-2 learns its position table like this. Some models use fixed sine waves instead, or build position into the Q · K comparison itself.
  • A rescaling step. Real models usually normalise x (layer normalisation: shift it to average 0 and scale it to a standard size) just before the Q, K and V layers. That keeps the numbers in a steady range. This page leaves it out to keep the circuits small.
  • One table or two. Skip-gram has a second table, context_vector, used to score candidate neighbours. A GPT-style model has a matching output table for scoring the next token at the very end. GPT-2 reuses the embedding table for this, so in that model the two tables are one.

Only the first layer sees embeddings

A Transformer stacks many blocks. Each block is a set of attention heads followed by a small ordinary network (an MLP). Only the first block gets embedding + position as its x. Every later block's x is the output of the block below it. Each block's output is added back on to its input (a "residual" connection), so the vector is refined layer by layer instead of replaced:

About the example numbers. The x vectors used on the rest of this page ([1, 0, 0] for "the" and so on) are made up to keep the arithmetic readable. They are not taken from your trained skip-gram embeddings, which have 32 numbers each.

3. The only part we need: the neuron

In the codeNeuron.forwardneuron.py lines 53–65

Here is everything a neuron in your code does:

def forward(self) -> float:
    total = 0.0
    for synapse in self._synapses_in:
        total += synapse.weight * synapse.from_neuron.value
    self._value = self.activation(total)
    return self._value

Your Neuron class already has two activation functions, identity and sigmoid. An attention head needs three more. Each still takes one number and gives back one number, so each is an ordinary activation function, a one-line static method just like sigmoid:

@staticmethod
def square(x: float) -> float:
    return x * x

@staticmethod
def exp(x: float) -> float:
    return math.exp(x)

@staticmethod
def log(x: float) -> float:
    return math.log(x)

The one thing a neuron cannot do. A synapse's weight is a number stored in the network. So a neuron can work out weight × value, but it cannot multiply two neuron values together. Attention needs that kind of multiplication three times: query × key (Steps 2–4), the division inside softmax (Step 5), and weight × value (Step 6). Most of this page is about how ordinary neurons get around this.

4. Step 1: Q, K and V are three layers

The query for "sat" is q_sat = x_sat · W_Q, a vector times a matrix. That is exactly what one fully connected layer of identity neurons computes. There is one input neuron for each number in x and one output neuron for each number in q, and every input is joined to every output by a synapse. The weight on the synapse from x[r] to q[c] is the matrix entry W_Q[r][c].

This is the same layout as your SkipGramNetwork. A column of the matrix is the weights on the synapses into one neuron, like context_vector. A row is the weights on the synapses out of one neuron, like embedding. The key and value layers are built the same way, each with its own weights W_K and W_V. Together that is 3 × 6 = 18 synapses per token.

Every token needs its own query, key and value, so the three layers are repeated once for each token. The copies all use the same weights. "the", "cat" and "sat" are all multiplied by the same W_Q, the same W_K and the same W_V:

With Synapse objects, "shared" means the three synapses must always hold equal weights. During training their nudges are added together and the total is applied to all three, so they never drift apart (see section 11). Running the same network on every token in a sentence like this is what lets a Transformer handle a sentence of any length with a fixed number of weights.

5. Step 2: Multiplying two neuron values

Next the head needs the score q_sat · k_cat. This is where attention differs from your skip-gram network. In skip-gram the dot product was easy, because one of the two vectors was the synapse weights:

The fix is a piece of school algebra. Expand both squares:

(a + b)² = a² + 2ab + b²
(a − b)² = a² − 2ab + b²
(a + b)² − (a − b)² = 4ab

Every part of this is something a neuron can do. Adding a and b is a neuron with two synapses of weight +1. Subtracting is weights +1 and −1. Squaring is the square activation. Taking a quarter of the difference is an output neuron with weights +¼ and −¼. The result is a multiply block: two square neurons and six synapses, with weights fixed by the construction.

Other ways to multiply two valuesoptional

The square trick is used here because it needs nothing but weighted sums and a one-input activation function, which is exactly what your Neuron class provides. Other designs reach the same product differently:

  • Product neurons (also called "sigma-pi" units) multiply their inputs instead of adding them. This means adding a new kind of neuron.
  • Gated synapses have a weight that is set by another neuron's value while the network runs. The product q[c] × k[c] becomes "q[c] passing through a synapse whose weight is k[c] right now". This is how matrix code effectively treats K, and section 12 comes back to it.
  • Log domain: for positive numbers, a × b = exp(log a + log b). This is two log neurons and an exp neuron. It fails for zero and for negative values, which queries and keys often have.

All of these give the same number. The neuron count changes, but the attention mechanism doesn't.

6. Step 3: The dot product q · k

A dot product is a sum of products: q · k = q[0]×k[0] + q[1]×k[1]. We have a block for each product, and the sum is free: point both blocks at the same output neuron, and its weighted sum adds them. That neuron is the score.

The formula also divides by √dk = √2. That costs nothing either. Each block's output weights of ±¼ simply become ±¼ × 1/√2 = ±0.177. The scaling lives in four fixed synapse weights.

Why scale by √dk? With 64 numbers per vector, as in GPT-2, a dot product adds up 64 products. A typical score is then about √64 = 8 times bigger than any one product. Scores that large push softmax to put nearly all the weight on a single token, and training slows down. Dividing by √dk keeps the scores in a useful range.

7. Step 4: The score grid and the T in KT

Each query is compared with every key, so there is one score for every (query token, key token) pair. Arranged as a grid, with query tokens down the side and key tokens across the top, the grid is the matrix product Q · KT. Entry (i, j) of a matrix product is row i of the left matrix times column j of the right matrix. Q has one row per token, so row i is q_i. For column j to be k_j, the keys have to be stood on end as columns. That is all the transpose does.

The grid also shows the causal mask. In a GPT-style model, which predicts the next token, a token may only look at itself and the tokens before it. Otherwise it could peek at the answer during training. In matrix code the masked scores are set to −∞ so that softmax gives them a weight of exactly 0. In the network it is simpler: those score neurons and their synapses are never built. Of the 9 cells, 6 have neurons.

8. Step 5: Softmax from exp and log neurons

Softmax turns one query's row of scores into weights that are all positive and add up to 1:

a(i, j) = exp(score(i, j)) / Σj' exp(score(i, j'))

Dividing by the sum is another multiplication of two neuron values (by 1/sum), so it would need more multiply blocks. Logarithms avoid that, because dividing by a number is the same as subtracting its log before taking exp:

a(i, j) = exp( score(i, j) − log Σj' exp(score(i, j')) )

Every piece of that is one neuron. There is an exp neuron per score, a sum neuron with weight-1 synapses from all of them, and a log neuron. Finally there is one attention neuron per score, with exp activation, fed by its score through a +1 synapse and by the log through a −1 synapse.

sum = 7.049, log(sum) = 1.953. The three weights add up to 1.000. "sat" pays 76% of its attention to "cat".

This is how real code does it too. Writing softmax as exp(score − log Σ exp) is called the log-sum-exp form. Libraries use it because it is numerically safer. They usually also subtract the largest score first, which is one more fixed −1 synapse. So the neuron version here is not a toy rewrite.

9. Step 6: Mixing the values

The output for "sat" is the weighted mix of all the values it is allowed to see: out_sat = Σj a(sat, j) · v_j. Each term multiplies an attention weight, a neuron value, by a value number, which is also a neuron value. So this step uses multiply blocks again. The Σ is free again too, because all the blocks feed one output neuron.

keya(sat, key)v_keya × v

The new vector for "sat" is [0.43, 1.04], and 76% of it comes from the value of "cat". That is the point of attention. Before this layer, the vector for "sat" only described "sat". Now it carries information about who sat, and later layers can use it.

In a full Transformer, several heads like this one run side by side. Their outputs are joined end to end and passed through one more layer with weights W_O. That layer is another plain layer of identity neurons, built exactly like Step 1.

11. Training: which synapses learn

Count the synapses in the network above and sort them into two kinds:

  • Learned: the embedding and position tables that make x (section 2), and the synapses from x into the q, k and v neurons. There are 54 of them (18 per token), but they hold only the 18 distinct weights of W_Q, W_K and W_V, because the copies are shared.
  • Fixed: everything else, which is the ±1, ±¼ and ±0.177 weights of the multiply blocks, the 1s of the sum neurons and the +1/−1 of the softmax. These are part of the design of attention, not something it learns. Training must leave them alone.

Backpropagation works just as it does in your skip-gram train_pair. The error flows backwards through each neuron and is multiplied by the slope of its activation function. Every activation here has a simple slope: identity has 1, square has 2x, exp has its own value and log has 1/x. A multiply block's output is exactly a × b, so the gradient that reaches a is the incoming gradient times b. That is the same rule your skip-gram code uses when it nudges w_in by grad × w_out. When the error reaches the shared Q, K and V synapses, the nudges from all token positions are added together and applied to the one shared weight.

What does training teach the head? W_Q and W_K learn which tokens should find each other. In the example, the query of "sat" lines up best with the key of "cat". W_V learns what information to pass along once a token has been found.

12. How real code does it

Nobody builds attention out of Neuron objects in practice. Real code writes it as a few matrix operations, roughly softmax(Q @ K.T / sqrt(d_k) + mask) @ V, and a GPU runs thousands of multiply-adds at once. That is the same arithmetic as the network above, packed differently:

  • A matrix × vector is a layer of neurons, with the matrix entries as its synapse weights.
  • A matrix × matrix where both sides are activations, such as Q · KT or A · V, is a grid of products of two values. On a GPU each product is a single multiply instruction. Built from your neurons, each product is a multiply block.

The neuron picture also shows how big attention really is. In GPT-2 small, with 1,024 tokens and d_k = 64, one head's score grid alone takes 1,024 × 1,024 × 64 ≈ 67 million products. That would be about 134 million square neurons, for one head in one layer.

Another way to see Step 4. Look at the score neuron again, using the "gated synapse" idea from Step 2. For a given sentence, k_cat acts like a set of synapse weights that q_sat passes through. Skip-gram's output neuron does exactly this with context_vector. The difference is that in skip-gram those weights are learned once and stored, while in attention they are recomputed for every sentence from the tokens themselves. That is why attention is often described as a layer whose weights depend on the input.

So a Transformer's attention head adds no new kinds of parts. It is built from the same neurons and synapses as skip-gram, plus three activation functions (square, exp and log). What is new is the wiring: fixed circuits that let the network multiply two of its own values together, so one token's vector can decide how much of another token's vector to take in.
